## Git Workflow

### Створені гілки та їх призначення
- **master**:Основна гілка проекту із стабільним кодом.
- **feature/movies**: Початкова розробка класів `Movie` та `AddFilmToList`.
- **feature/booking**: Додавання системи бронювання квитків та скасування бронювання.
- **feature/cancel-booking**: Реалізація методу `cancel_booking` та логіки скасування.
- **feature/search**: Додавання пошуку фільмів за назвою та режисером.
- **feature/favorites**: Реалізація класу `FavoriteManager` для роботи з обраними фільмами через JSON.
- **feature/menu**: Початкове оновлення головного меню додатку.
- **feature/menu-update**: Додавання стилізації меню за допомогою кастомних рамок.
- **feature/statistics**: Реалізація статистики та управління кількістю доступних квитків.
- **feature/discount**: Реалізація функції розрахунку знижки на квитки.

### Використання Git-інструментів

- **Merge та вирішення конфліктів**:
  - Конфлікт виник під час злиття гілки `feature/menu-update` у `master` у файлі `main.py` через одночасне редагування меню в обох гілках.
    - Конфлікт було вирішено вручну шляхом збереження актуальних пунктів меню, 
        збереження прапорців завантаження даних та видалення маркерів конфлікту (`<<<<<<<`, `=======`, `>>>>>>>`).

- **Rebase**:
  - Використовувався у гілці `feature/statistics` відносно `master` (`git rebase master`), 
        щоб відтворити коміти статистики поверх останніх змін `master` і зберегти чисту, лінійну історію проекту.

- **Cherry-pick**:
  - Застосовувався для перенесення точкового коміту з функцією розрахунку знижки (`"Add ticket discount"`) з гілки `feature/discount` 
        безпосередньо в гілку `master` за допомогою `git cherry-pick <commit-hash>`.

- **Stash**:
  - Використовувався для тимчасового збереження незакоммічених змін у гілці `feature/stash-test` за допомогою `git stash`, 
        що дозволило безпечно переключитися на іншу гілку та повернути зміни назад за допомогою `git stash pop`.
